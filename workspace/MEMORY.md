# MEMORY.md

## Purpose

Defines how the `memory` system should be used.

---

## Principles

- Memory is **contextual, not authoritative**
- Documentation and code always take precedence
- Memory helps with:
  - continuity across sessions
  - recovering past decisions
  - avoiding repeated mistakes

---

## Good Memory Entries

- "Chose X over Y because of Z constraint"
- "Fixed bug in payment flow caused by timezone mismatch"
- "Refactored auth module to use middleware pattern"

---

## Bad Memory Entries

- trivial steps
- obvious code behavior
- duplicated documentation

---

## Guidelines

- Be concise
- Be specific
- Focus on decisions and reasoning
- Avoid noise
